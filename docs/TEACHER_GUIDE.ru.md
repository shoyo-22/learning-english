# English Lab: руководство учителя и руководителя исследования

Это руководство описывает работу с текущей версией English Lab: подготовку урока, задания для учеников, сбор реальных результатов и аккуратную интерпретацию данных. Приложение можно запускать локально; наличие опубликованного сайта не предполагается.

Установка Node.js, Git и пакетов, настройка базы, тестовые настройки, команды запуска и техническое устранение ошибок находятся в [инструкции по установке](INSTALLATION.ru.md). Действия ученика описаны в [руководстве ученика](STUDENT_GUIDE.ru.md). Техническая карта проекта и проверки — в [README](../README.md) и [QA.md](../QA.md).

## 1. Что учитель получает в этой версии

English Lab — учебное приложение с упражнениями, материалами для самостоятельной работы и небольшим исследовательским модулем. Учётных записей «ученик» и «учитель», электронного журнала, списка класса и входа по тестовому логину в приложении нет. Роль учителя здесь организационная: выбрать задания, объяснить правила исследования и проверить реальные результаты.

| Раздел                               | Для чего использовать на занятии                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| Главная, `/`                         | Краткое знакомство с проектом и переход к занятиям.                                  |
| Обучение / Learn, `/learn`           | Приёмы работы с лексикой, грамматикой, говорением, письмом и чтением.                |
| Практика / Practice, `/practice`     | 40 подготовленных упражнений: 10 на каждом уровне A1, A2, B1, B2.                    |
| Ассистент / Assistant, `/assistant`  | Демонстрация заранее подготовленных объяснений и вопросов.                           |
| Промпты / Prompts, `/prompts`        | 12 копируемых примеров запросов; поиск и фильтр по категории.                        |
| Говорение / Speaking, `/speaking`    | 7 тем, по 5 вопросов для ответа вслух.                                               |
| Исследование / Research, `/research` | Тесты Before/After, парные сравнения, агрегированная активность и описание методики. |
| О проекте / About, `/about`          | Тема, цель, гипотеза, авторство, ограничения и сведения о данных.                    |

Обозначения A1–B2 помогают выбрать сложность учебных материалов. Они не означают, что приложение проводит сертифицированное определение уровня CEFR.

### Два независимых ограничения

1. **Ассистент всегда работает как демо.** Он не обращается к OpenAI и не требует аккаунта, подписки или API-ключа OpenAI. Подключение Supabase не превращает его в настоящую языковую модель.
2. **Сохранение исследования требует настроенной базы.** Без неё задания проверяются, но результаты практики не сохраняются, а Before/After недоступны.

Это разные настройки: приложение с работающей исследовательской базой по-прежнему использует подготовленные ответы ассистента.

## 2. Выберите режим занятия

| Возможность                                       | Без подключённой базы                              | С настроенной и доступной Supabase          |
| ------------------------------------------------- | -------------------------------------------------- | ------------------------------------------- |
| Учебные материалы, промпты, вопросы для говорения | Доступны                                           | Доступны                                    |
| Проверка упражнений и пояснения                   | Доступны при работающем локальном сервере          | Доступны                                    |
| Подготовленные ответы ассистента                  | Доступны                                           | Доступны                                    |
| Долговременное сохранение практики                | Нет; интерфейс сообщает о несохранённом результате | Да, после успешного завершения и сохранения |
| Before/After и личная пара                        | Недоступны                                         | Доступны при выполнении порядка этапов      |
| Общие реальные результаты                         | Недоступны                                         | Появляются после сохранения реальных данных |
| Пример диаграммы                                  | Можно включить с явной пометкой «демо»             | Можно включить, пока нет реальных пар       |

Для обычного знакомства или подготовки преподавательского показа используйте режим без базы. Для сбора исследовательских данных подготовьте базу по установочной инструкции заранее.

Если каждый ученик установил приложение у себя без базы, учитель не получит их результаты в общей диаграмме. Адрес `http://localhost:3000` на компьютере ученика обозначает именно компьютер этого ученика, а не компьютер учителя.

Серверный секрет Supabase предоставляет расширенный доступ к исследовательской базе. Его не нужно выдавать ученикам для работы в браузере. Для общего исследования предпочтителен один сервер приложения под контролем ответственного взрослого и доступ учеников к нему через браузер. Подготовку такого доступа согласуйте с техническим ответственным; обычный локальный запуск сам по себе не создаёт общедоступный сайт. На личных ученических компьютерах можно независимо запускать демо без секретов.

## 3. Подготовка учителя до урока

### Проверьте приложение

1. Выполните установку и запустите сервер по [INSTALLATION.ru.md](INSTALLATION.ru.md). Оставьте терминал с сервером открытым.
2. Откройте адрес, который напечатал сервер. Не подменяйте адрес другой машиной или старой ссылкой из скриншота.
3. Выберите язык интерфейса: English (`en`), Русский (`ru`) или Қазақша (`kk`). Переключатель находится в верхней части страницы; на узком экране навигация открывается кнопкой меню.
4. Просмотрите Learn, Practice, Assistant, Prompts и Speaking. Убедитесь, что задания соответствуют вашему уроку.
5. Если нужны реальные данные, выполните проверку подключения из установочной инструкции и убедитесь, что Research не сообщает о недоступном хранилище.
6. Проверьте читаемость на проекторе и доступность клавиатуры. Кнопкой Tab можно перемещать фокус; вкладки Learn переключаются стрелками; мобильное меню и диалоги закрываются Escape.
7. Установите продолжительность работы и заранее выберите уровень и категорию практики. Запишите условия, если сравниваете результаты участников.

Для проверки интерфейса не проходите фиктивные Before/After в рабочей исследовательской базе. Используйте демо без базы либо отдельную тестовую базу. Автоматические проверки проекта используют изолированные данные; технические безопасные проверки описаны в установочной инструкции.

### Договоритесь о правилах занятия

Объясните ученикам:

- участие в исследовательских тестах добровольное; учебные разделы можно использовать отдельно;
- Before и After выполняются самостоятельно, без подсказок учителя, соседей, готовых ответов и внешнего ассистента;
- во время учебной практики обсуждение правил и помощь разрешены в согласованном вами объёме;
- первый сохранённый результат каждого исследовательского теста окончательный;
- ошибки в практике — материал для разбора, а не причина добиваться «идеального» исследовательского результата повторными регистрациями;
- нельзя вводить личные сведения в демо-чат или в промпты.

Перед работой с несовершеннолетними согласуйте формат участия, информирование семьи и обращение с данными по правилам вашей организации. Это руководство не устанавливает юридические требования и не заменяет школьную процедуру согласования.

## 4. Пример обычного урока на 40–45 минут

Этот сценарий не требует исследовательской базы и не создаёт выводов об эффективности ChatGPT.

| Время       | Действия учителя и учеников                                                                                                                        | Результат                           |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 0–5 минут   | Откройте Learn. Выберите одну цель: например, объяснить разницу между настоящим и прошедшим временем.                                              | Понятная цель урока.                |
| 5–10 минут  | В Assistant отправьте `Correct my sentence: I go to school yesterday.` Обсудите исправление и попросите учеников объяснить правило своими словами. | Разбор подготовленного примера.     |
| 10–20 минут | В Practice задайте одинаковый или подходящий группе уровень. Ученики отвечают и читают обратную связь после каждого ответа.                        | Практика с пояснениями.             |
| 20–30 минут | В Speaking выберите тему. Ученики отвечают вслух в парах: полное предложение, причина, пример.                                                     | Устная практика с партнёром.        |
| 30–38 минут | В Prompts найдите подходящий запрос. Разберите, где указан уровень, задача, желаемый формат ответа и требование дождаться ответа ученика.          | Навык составления учебного запроса. |
| 38–45 минут | Попросите назвать изученное правило, привести новый пример и выбрать следующий шаг для самостоятельной работы.                                     | Короткая рефлексия.                 |

Если база отключена, итоговый процент практики всё равно можно обсудить на экране. Сообщение «результат не сохранён» в этом режиме ожидаемо; оно не отменяет показанную проверку ответов.

Не обещайте автоматическую проверку нового свободного предложения ассистентом: текущий демо-режим умеет отвечать только на ограниченный набор сценариев. Незнакомые ответы проверяет учитель.

## 5. Как организовать учебные разделы

### Practice: индивидуальная и групповая работа

Доступны уровни A1, A2, B1 и B2. Выбор всех категорий даёт 10 заданий; отдельная категория — 2 задания. Категории: Vocabulary, Grammar, Choose the Correct Answer, Fill in the Blanks и Correct the Mistake.

1. Ученик выбирает уровень и категорию, затем запускает практику.
2. В вопросах с вариантами выбирает ответ; в текстовых заданиях вводит слово или исправленное предложение.
3. Нажимает Check Answer / «Проверить ответ».
4. Читает правильный ответ и объяснение. В процент результата входит первый проверенный ответ на вопрос.
5. Переходит к следующему вопросу. После последнего нажимает See Final Score / кнопку итогового результата.
6. При подключённой базе ждёт подтверждения сохранения. Если возникла временная ошибка, повторяет сохранение на том же итоговом экране.
7. Открывает Review your answers / разбор ответов и обсуждает правило, которое вызвало затруднение.

Полезное домашнее задание: один небольшой набор, два собственных примера по ошибкам и повторение правила на следующий день. Приложение не назначает домашние задания и не рассылает их автоматически.

Результаты разных уровней, категорий и повторных попыток не следует считать напрямую сопоставимыми. Два вопроса одной категории дают только 0%, 50% или 100%; это грубый учебный индикатор. В истории отображаются последние пять сохранённых практик текущего браузера, а не журнал всего класса.

Проверка свободного ввода сопоставляет ответ с подготовленным эталоном после нормализации регистра, пробелов, некоторых кавычек и конечной пунктуации. Она не оценивает все возможные правильные перефразировки. Если естественный вариант ученика отмечен ошибкой, разберите его сами и отдельно решите, нужно ли улучшить задание. Не меняйте оценки выборочно ради желаемого результата исследования.

### Assistant: что показать и как объяснить границы

Работающие демонстрационные запросы:

```text
Correct my sentence: I go to school yesterday.
Explain Present Perfect simply.
Give me five B1 words about technology.
Give me words about travelling.
Ask me an English speaking question.
```

Дополнительные подготовленные исправления включают `She like music.`, `He didn’t went home.` и `I look forward to hear from you.` После мини-урока Present Perfect можно ответить `have` или `has` на предложенное упражнение. В разговорном сценарии ученик отвечает вслух, затем вводит предложение, чтобы получить следующий заранее подготовленный вопрос.

Ассистент не генерирует произвольные тексты, не проверяет новое сочинение надёжным образом, не оценивает произношение и не определяет уровень ученика. Он может сообщить, что запрос выходит за пределы демо. Это ожидаемое поведение.

Сообщения обрабатывает сервер этого приложения; они не отправляются в OpenAI и не записываются в исследовательскую базу. История чата хранится в текущем состоянии страницы: не рассчитывайте на её восстановление после перезагрузки или закрытия. Очистка диалога требует подтверждения.

### Prompts: обучение формулировке запроса

Предложите ученикам найти запрос по категории или поиску. Поиск учитывает английский текст и переведённые заголовки/категории. При отсутствии результатов сбросьте фильтры.

Кнопка копирования помещает английский запрос в буфер обмена. Ученик заменяет `[your sentence]`, `[your paragraph]` или `[your draft]` собственным безопасным учебным текстом. Переход в Assistant может заранее заполнить поле запроса, но не расширяет возможности демо.

Часть промптов описывает задачи для полноценного внешнего ассистента, например создание текста для чтения или проверку сочинения. Текущий встроенный демо-ассистент не выполняет весь этот набор. Использование внешнего сервиса — отдельное решение учителя с отдельными условиями доступа; для работы English Lab оно не требуется.

### Speaking: оценку даёт человек

Темы: семья, школа, хобби, путешествия, будущая профессия, технологии и окружающая среда. Для каждой темы есть пять вопросов.

Попросите ученика ответить на один вопрос, дать причину и пример. Напарник может задать уточнение; учитель отдельно отмечает понятность, полноту ответа и использование изученной лексики. Кнопка Copy Questions копирует вопросы, Try Another Topic переключает тему.

Раздел не записывает звук, не использует микрофон для анализа и не выставляет баллы за произношение или беглость. Значок микрофона — обозначение устного упражнения. Если вы добавляете свою рубрику для устных ответов, ведите её отдельно: она не попадёт автоматически в результаты Research.

### Языки интерфейса

Переключатель en/ru/kk меняет навигацию, подсказки, описание разделов, сообщения и подписи диаграмм. Английские упражнения, варианты ответов, объяснения правил, копируемые промпты и ответы демо-ассистента остаются на английском: это учебное содержание.

Смена языка не должна сбрасывать текущие ответы или диалог. Выбор сохраняется в cookie браузера. Перезагрузка страницы, уход из незавершённого упражнения и очистка cookies — другие действия; не используйте их как способ смены языка.

## 6. Как собрать настоящие пары Before → After

### Зафиксируйте протокол до начала

Для небольшого исследования запишите отдельно:

- цель и проверяемое утверждение;
- версию приложения и теста: в текущей версии используется `v1`;
- состав выбранных упражнений, уровень и длительность работы;
- разрешённую помощь во время практики и запрет помощи во время тестов;
- даты, общее число приглашённых, число завершивших этапы и известные технические сбои;
- использовался ли только встроенный демо-ассистент или какие-либо внешние инструменты.

Не называйте работу со встроенным демо полноценным экспериментом с ChatGPT. Содержательные утверждения о настоящей модели требуют другого вмешательства и отдельного корректного протокола.

### Подготовьте браузеры

Для всей последовательности одному ученику нужен один и тот же браузерный профиль, устройство и адрес приложения. Не чередуйте `localhost`, `127.0.0.1` и сетевой адрес: это разные имена сайта для cookies. Не используйте режим инкогнито для исследования, которое нужно продолжить позже; при закрытии такого сеанса идентификатор может исчезнуть.

Один общий браузерный профиль на нескольких учеников смешивает их участие. При работе на общих компьютерах организуйте отдельные профили для реальных участников до начала исследования. Не создавайте дополнительные профили одному и тому же участнику ради повторной попытки. Объясните порядок техническому ответственному заранее.

Учительскую демонстрацию проводите без записи в рабочую базу либо в отдельной тестовой базе. Очистка cookies сама по себе не удаляет старые данные из Supabase.

### Проведите этапы

1. **Before, около 5 минут.** Ученик открывает Research, запускает Before Test, самостоятельно отвечает на все 8 вопросов и отправляет результат. Дождитесь отметки о сохранении.
2. **Учебная работа, 15–20 минут.** Ученик изучает выбранное правило, выполняет задания и разбирает пояснения. После Before он должен завершить хотя бы одну практику до итогового экрана и получить подтверждение сохранения.
3. **Проверка готовности.** Ученик возвращается в Research. При необходимости нажимает Refresh status / обновление статуса. Демо-переписка, копирование промптов, посещения страниц и незавершённые упражнения не заменяют сохранённую практику.
4. **After, около 5 минут.** Ученик в том же браузере самостоятельно проходит вторую форму из 8 вопросов и сохраняет результат.
5. **Подтверждение пары.** На странице появляется личное сравнение. Обновите результаты исследования: новая пара должна попасть в агрегаты.
6. **Разбор.** Обсудите изученные правила и ограничения измерения, не раскрывая ключи исследовательского теста будущим участникам.

15–20 минут — рекомендация, а не программный таймер. Сервер проверяет порядок сохранённых этапов, но не контролирует фактическое время занятий, самостоятельность ответов или личность человека.

Для обычного школьного занятия можно выделить 45 минут: 5 минут на инструктаж, 5 на Before, 15–20 на обучение, 5 на After и 10–15 на обсуждение. Если техническая подготовка занимает больше времени, проведите её до начала сбора.

### Что программа защищает, а что остаётся ответственностью учителя

Первая сохранённая отправка Before и After окончательна для браузера и версии теста. Повтор того же запроса не создаёт новую попытку. Завершённая практика также сохраняется с идентификатором попытки, чтобы повтор сохранения не дублировал её.

В тестах нет выдачи правильных ответов и объяснений до или после отправки; в учебной практике обратная связь предусмотрена. Не переносите ключи из исходного кода в общедоступное руководство для участников. Не обновляйте вопросы теста в середине исследования.

Технические ограничения не подтверждают, что перед компьютером находится один определённый ученик. Достоверность организации урока, одинаковые условия и фиксацию отклонений обеспечивает учитель.

## 7. Как читать Research без завышенных выводов

### Основные показатели

| Показатель                      | Что означает                                                                                   | Чего не означает                                           |
| ------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Completed assessment pairs      | Число идентификаторов браузера с обоими тестами одной версии.                                  | Проверенное число уникальных учеников.                     |
| Average Before                  | Средний результат Before только для завершённых пар.                                           | Средний результат всех начавших Before.                    |
| Average After                   | Средний результат After для тех же пар.                                                        | Результат всего класса, включая незавершивших.             |
| Average difference              | Разность средних After и Before в процентных пунктах.                                          | Доказанный эффект ChatGPT или относительный процент роста. |
| Anonymous browser identifiers   | Число зарегистрированных браузерных идентификаторов.                                           | Число людей.                                               |
| Recorded visits                 | События посещения приложения; обычно инициализация в сеансе вкладки.                           | Число участников или число отдельных учебных дней.         |
| Completed practice sessions     | Число сохранённых завершённых практик.                                                         | Число учеников, освоивших тему.                            |
| Questions in completed practice | Вопросы в сохранённых завершённых практиках.                                                   | Все клики, все попытки ответа или все начатые задания.     |
| Average practice score          | Средний балл сохранённой практики разной сложности.                                            | Сопоставимый с Before/After итоговый уровень.              |
| AI learning exchanges           | Сохранённые метаданные настоящих обменов из поддерживаемых исторических данных, если они есть. | Число текущих демо-ответов; они сюда не записываются.      |

Если Before сохранён, а After отсутствует, такой участник не входит в парные средние. Поэтому сообщайте отдельно число начавших и число завершивших протокол, если ведёте такую запись вне приложения. Не дописывайте пропущенный After нулём или средним по группе.

Все реальные пары данной базы и версии входят в общие результаты. В этой версии нет интерфейсного фильтра по классу, уроку, дате или отдельному исследованию. Если нужна чистая выборка, используйте отдельную исследовательскую базу или выполняйте заранее описанный анализ разрешённой выгрузки вне приложения. Не называйте общую диаграмму результатом одного урока, если база содержит другие занятия.

### Проценты и процентные пункты

У каждого теста 8 вопросов, по 2 на Vocabulary, Grammar, Speaking и Writing. Результат навыка может быть 0%, 50% или 100%; общий результат — среднее четырёх навыков, с шагом 12,5 процентного пункта. Средние по нескольким парам могут иметь другие дробные значения.

Если среднее изменилось с 60% до 75%, разность равна **+15 процентным пунктам**. Относительный прирост в этом примере составляет 25%, но приложение показывает именно +15 п.п. Не заменяйте одну величину другой.

Демонстрационные столбцы и средние групп могут принимать значения, невозможные для одного теста из восьми вопросов. Это не делает их отдельными индивидуальными результатами.

### Пределы интерпретации

- Speaking в исследовательском тесте проверяет выбор подходящей реплики; это не запись речи и не оценка произношения или беглости.
- Writing проверяет знание редактирования; это не независимое написание и экспертная оценка сочинения.
- Reading представлен учебными рекомендациями и промптами, но не отдельной шкалой в четырёхкомпонентном исследовательском тесте.
- По два вопроса на навык дают очень ограниченную точность. Формы похожи по структуре, но не прошли психометрическое выравнивание сложности.
- Нет контрольной группы и автоматического контроля длительности обучения. На разницу влияют повторное тестирование, случайность, различия форм, помощь и другое обучение.
- Несколько устройств у одного человека увеличивают число идентификаторов; один профиль у нескольких человек, наоборот, смешивает их данные.
- Завершившие оба теста могут отличаться от тех, кто остановился после первого. Диаграмма не решает эту проблему отбора.
- Повышение результата описывает выполнение этих задач после занятий; оно не доказывает причинный эффект платформы или ChatGPT.

Пример корректной формулировки: «В текущей базе получено N пар браузерных записей версии v1. Средний результат по этим восьми заданиям изменился с X% до Y%, то есть на Z п.п. Участники работали с платформой и подготовленным демо-ассистентом; без контрольной группы и дополнительной проверки мы не можем приписать изменение реальному ChatGPT».

Подставляйте только реальные проверенные значения. Если пар пока нет, так и напишите.

### Демонстрационная диаграмма

Кнопка View labeled demo chart показывает заранее записанные иллюстративные значения. Они не создают участников, не добавляются в Supabase и не смешиваются с реальными парами. При появлении реальных пар график использует реальные агрегаты.

На презентации оставляйте видимой пометку «демо». Не называйте эти столбцы результатом класса и не придумывайте число участников. Закрыть пример можно кнопкой Hide demo data.

## 8. Данные, доступ и работа с несовершеннолетними

При подключённой базе приложение хранит подписанный анонимный идентификатор браузера, время активности, результаты завершённых практик, идентификаторы заданий и правильность ответов, результаты тестов и отдельные события использования. Необработанные ответы практики не сохраняются как текст. Поля для фамилии, телефона, электронной почты, точного адреса или геолокации не предусмотрены.

Приложение не сохраняет переписку демо-ассистента в исследовательские таблицы и не отправляет её в OpenAI. При этом текст проходит через сервер приложения, а инфраструктура может иметь собственные технические журналы. Не обещайте ученикам отсутствие любых следов во всех системах.

Для учебного исследования:

1. Объясните простыми словами, что сохраняется, для чего и кто отвечает за базу.
2. Предложите работу с материалами без обязательного прохождения Before/After. Учтите: отказ от теста не отключает общие события активности в приложении с подключённой базой; для занятия без такой записи используйте демо без базы.
3. Просите использовать вымышленные примеры в письме и говорении, если вопрос может раскрыть частные сведения. Например, можно описывать вымышленную семью или город.
4. Храните доступ к Supabase и секреты у ответственного за исследование. В ученической версии браузера нет административного редактора результатов.
5. Публикуйте агрегаты и объяснения методики. Не распространяйте таблицу браузерных идентификаторов или её сопоставление с фамилиями как часть презентации.
6. Заранее определите срок хранения и порядок обращения к ответственному по вопросам данных. Автоматического интерфейса удаления своих записей в приложении нет.

Если организация отдельно ведёт соответствие «ученик — исследовательский код», храните его отдельно с ограниченным доступом. Не вставляйте фамилии вместо технических идентификаторов и не передавайте секреты для поиска записей ученикам. Связь с конкретным человеком превращает такую таблицу в иной по смыслу набор данных, чем обезличенная диаграмма.

Очищенные cookies не удаляют записи базы. Они также могут лишить пользователя возможности автоматически продолжить прежнюю пару. Индивидуальные исправления или удаление данных выполняет ответственный через защищённые инструменты базы, понимая связанные записи и влияние на агрегаты; порядок технической работы указан в [README](../README.md).

## 9. Подготовка отчёта или защиты проекта

Перед показом:

1. Обновите информацию об авторе и руководителе.
2. Проверьте, что гипотеза обозначена как гипотеза, а заключение соответствует уже собранным данным.
3. Уточните режим: демонстрация интерфейса, исследование практики на платформе или отдельное исследование внешнего инструмента.
4. Обновите Research и сверьте реальные результаты с разрешённой выгрузкой из Supabase, если делали отдельный анализ.
5. Укажите версию теста, даты, число пар, условия занятий и ограничения.
6. Если настоящих пар нет, используйте только явно подписанный пример графика и сообщите, что сбор данных ещё не завершён.

Удобная последовательность показа: Home → Learn → подготовленный пример Assistant → Practice и пояснение ошибки → поиск и копирование Prompts → тема Speaking → Research и ограничения → About.

Выгрузку `assessments` может сделать ответственный в панели Supabase. В ней технические записи, поэтому отделяйте исходный экспорт от рабочей аналитической копии и журналируйте разрешённые изменения. Не вставляйте демонстрационные оценки в настоящую базу. В приложении нет кнопки экспорта персональной ведомости или редактора оценок учителя.

## 10. Как изменить авторство, учебный контент и переводы

Этот раздел предназначен учителю, который меняет свою локальную копию проекта, либо техническому помощнику. Остановитесь на редактировании содержимого; менять логику проверки ответов для обычного урока не требуется.

Перед правкой сохраните текущую рабочую версию в Git и создайте короткую рабочую ветку. После проверки изменения можно влить в локальную основную ветку по процессу из установочной инструкции.

| Иллюстративные показатели графика                             | Тот же файл, `demoResearch`; оставляйте их явно демонстрационными                                                      |

| Запросы библиотеки                                            | [`src/data/prompts.ts`](../src/data/prompts.ts)                                                                        |
| Темы и вопросы для ответа вслух                               | [`src/data/speaking.ts`](../src/data/speaking.ts)                                                                      |

| Подготовленные сценарии ассистента                            | [`src/lib/demo-tutor.ts`](../src/lib/demo-tutor.ts); правка требует понимания условий сценариев                        |

### Авторство

В `projectInfo` замените `[Student Name]` и `[Supervisor Name]` на согласованные варианты имени автора и руководителя. Не заполняйте отсутствующие сведения вымышленными именами. Если публикуете сведения несовершеннолетнего, используйте согласованный вашей организацией формат.

Тексты `projectInfo` проходят через систему переводов. Когда меняете английскую формулировку цели, темы или заключения, добавьте новую формулировку как ключ в словарь и переведите её на русский и казахский. Иначе в ru/kk эта строка останется на исходном языке. Имена можно оставить одинаковыми для всех языков.

### Переводы

В словаре английский исходный текст служит ключом:

```json
{
  "Your new message": {
    "ru": "Ваш новый текст",
    "kk": "Жаңа мәтініңіз"
  }
}
```

Добавляйте такой объект внутрь существующего словаря с корректными запятыми; не заменяйте им весь файл. Если в исходной строке есть параметр вроде `{score}`, `{total}` или `{type}`, сохраните его с тем же именем и фигурными скобками в обоих переводах. Не переводите технические идентификаторы категорий, URL, поля API и ключи вопроса.

Для учебных английских предложений, вариантов ответов и копируемых промптов перевод в словарь обычно не нужен: они намеренно остаются на английском. Переводите окружающие объяснения интерфейса, а не эталон ответа.

### Учебные вопросы и исследовательский тест

Для Practice сохраняйте уникальные `id`, допустимый уровень, категорию, английский вопрос, корректный эталон и объяснение. Банк и интерфейс сейчас рассчитаны на 40 вопросов — 10 на уровень и 2 на категорию. Произвольное добавление или удаление потребует обновить связанные подписи, проверки покрытия и ожидания сервера; поручите такую правку техническому помощнику.

Для исследовательских форм недостаточно заменить текст вопроса. Смена инструмента требует новой версии теста и согласованного изменения агрегирования базы, чтобы старые и новые формы не смешивались. Не редактируйте ключи и формы во время продолжающегося исследования. Общедоступный доступ учеников к исходному файлу с эталонами тоже следует учитывать при организации самостоятельного тестирования.

После изменений выполните проверки по [INSTALLATION.ru.md](INSTALLATION.ru.md), включая `npm run typecheck`, `npm run lint`, `npm test` и `npm run build`. Затем просмотрите затронутые страницы на en, ru и kk. Проверка типов не заменяет педагогическую вычитку и проверку казахского перевода носителем языка.
