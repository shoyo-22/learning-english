# English Lab: установка и запуск на своём компьютере

[Все инструкции](README.ru.md) · [Ученику](STUDENT_GUIDE.ru.md) · [Учителю](TEACHER_GUIDE.ru.md) · [Тестовые доступы](TEST_CREDENTIALS.ru.md)

Инструкция рассчитана на человека без опыта программирования. Все команды выполняются в **терминале**, по одной строке, без символов разметки вокруг них. После команды дождитесь завершения; сервер запускается последним и продолжает работать, пока его не остановить.

## 1. Выберите вариант запуска

| Вариант                | Что установить                     | Что работает                                                                                | Кому подходит                                                  |
| ---------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Ссылка от учителя      | Только браузер                     | Возможности зависят от настройки сервера учителя                                            | Ученику на общем уроке                                         |
| Локальное демо         | Node.js с npm                      | Все учебные страницы, проверка практики, подготовленный помощник; результаты не сохраняются | Знакомство с платформой, самостоятельная практика, презентация |
| Полный локальный режим | Node.js с npm и Docker             | Дополнительно сохранение практики и исследовательские тесты Before / After                  | Учителю для репетиции, ученику для отдельного учебного проекта |
| Общий сайт класса      | Сервер и отдельный Supabase-проект | Общая база результатов, доступ по одному адресу                                             | Учителю с техническим ответственным                            |

**ИИ-помощник во всех этих вариантах демонстрационный.** Подключение базы не превращает его в настоящий ChatGPT. Аккаунт OpenAI, платный API и переменные `OPENAI_*` не нужны.

Установка базы на каждом ноутбуке создаёт независимые наборы данных. Они не объединятся в диаграмму учителя автоматически. Для общего исследования используйте один подготовленный сайт и одну базу.

## 2. Какие программы нужны

| Программа                         | Версия / назначение                                          | Обязательна?                  |
| --------------------------------- | ------------------------------------------------------------ | ----------------------------- |
| Браузер                           | Актуальный Chrome, Edge, Firefox или Safari                  | Да                            |
| Node.js                           | Рекомендуется **24 LTS**; минимальная версия проекта — 22.13 | Для запуска своей копии       |
| npm                               | Устанавливается вместе с Node.js                             | Для запуска своей копии       |
| Docker Desktop либо Docker Engine | Запускает локальные сервисы Supabase                         | Только полный локальный режим |
| Git                               | Получение и обновление исходников из репозитория             | Нет, если получен ZIP         |
| VS Code                           | Удобное редактирование файлов и встроенный терминал          | По желанию                    |

Версии библиотек закреплены в `package-lock.json`. Команда `npm ci` устанавливает сразу Next.js, React, TypeScript, Tailwind CSS, shadcn/ui/Radix, Supabase SDK, Supabase CLI и остальные зависимости. **Отдельно устанавливать каждый пакет, Python, PostgreSQL или глобальную Supabase CLI не требуется.**

Первой установке нужен интернет: npm скачивает пакеты, Docker — образы объёмом в несколько гигабайт. Выделите запас места на диске. После загрузки зависимостей и образов локальное приложение работает без облачных ключей. Шрифты включены в проект через npm-пакеты.

### Windows 11 / поддерживаемая версия Windows 10

1. Скачайте установщик **Node.js 24 LTS** для своей архитектуры с [официальной страницы Node.js](https://nodejs.org/en/download). Оставьте включёнными npm и добавление в PATH.
2. Завершите установку и заново откройте PowerShell или Windows Terminal.
3. Проверьте:

```powershell
node --version
npm --version
```

Первая команда должна показать `v24.x.x` или совместимую версию от 22.13. Если PowerShell блокирует `npm.ps1`, используйте **`npm.cmd` вместо `npm` во всех командах**, например `npm.cmd ci`. Менять системную политику выполнения скриптов для этого не нужно.

Для полного локального режима установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/), выберите Linux containers / WSL 2 backend и запустите приложение Docker Desktop. Требования к Windows, виртуализации и WSL приведены на странице установщика. Если WSL ещё нет, в PowerShell **от имени администратора**:

```powershell
wsl --install
wsl --update
```

Перезагрузите компьютер, если этого попросит установщик. В этой инструкции команды проекта выполняются в обычном PowerShell на Windows. Не смешивайте `node_modules`, установленные в Windows, с запуском той же папки из Linux/WSL: для WSL нужна отдельная копия с собственной установкой пакетов.

### macOS

1. Установите **Node.js 24 LTS** с [официальной страницы](https://nodejs.org/en/download). Выберите подходящий установщик для macOS.
2. Откройте **Терминал** через Spotlight (`⌘ Space` → «Терминал»).
3. Проверьте `node --version` и `npm --version`.

Для полного режима установите [Docker Desktop для Mac](https://docs.docker.com/desktop/setup/install/mac-install/): Apple Silicon для M-серии или Intel для Intel Mac. Откройте Docker Desktop и дождитесь готовности движка.

Не запускайте команды `npm` через `sudo`. Если Node.js установлен через менеджер версий, для этого проекта выберите Node 24.

### Linux

Ниже пример для Ubuntu/Debian с Bash. На другом дистрибутиве используйте его способ установки `curl`, а затем менеджер версий Node.js.

```sh
sudo apt update
sudo apt install -y curl ca-certificates
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
```

Последняя команда — установщик из [официального проекта nvm](https://github.com/nvm-sh/nvm). После неё **закройте и заново откройте терминал**, затем:

```sh
nvm install 24
nvm use 24
nvm alias default 24
node --version
npm --version
```

В папке проекта есть `.nvmrc`, поэтому в дальнейшем можно выполнять `nvm use`.

Для полной локальной базы установите Docker по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/) либо [выберите свой Linux-дистрибутив](https://docs.docker.com/engine/install/). Проверьте, что `docker info` работает от вашей обычной учётной записи. Если доступ к сокету Docker запрещён, настройку должен выполнить администратор по документации Docker; запуск всего проекта через `sudo` не нужен.

### Проверка Docker — только для полного режима

```sh
docker --version
docker info
```

Вторая команда должна вывести сведения о **Server**, а не ошибку подключения. Для демо Docker вообще не нужен. Docker Desktop требует принятия его условий использования; при установке на школьные компьютеры это делает ответственный за ПО.

## 3. Получите проект и откройте нужную папку

### Вариант A — ZIP, полученный от автора или учителя

1. Распакуйте `english-lab-classroom.zip` целиком, например в `Documents/english-lab-classroom`.
2. Найдите папку, внутри которой лежат **`package.json` и `package-lock.json`**. Это корень проекта.
3. Откройте эту папку в VS Code и выберите **Terminal → New Terminal**, либо перейдите в неё из обычного терминала.

Windows, пример пути — замените имя пользователя своим:

```powershell
cd "C:\Users\YOUR_NAME\Documents\english-lab-classroom"
dir package.json
```

macOS/Linux, пример:

```sh
cd "$HOME/Documents/english-lab-classroom"
ls package.json
```

Если архив распаковался с дополнительной вложенной папкой, сначала зайдите в неё. Название папки не обязательно совпадает с примером. Не запускайте проект прямо внутри окна ZIP-архива.

### Вариант B — Git

Установите Git с [официального сайта](https://git-scm.com/downloads), если выбираете этот способ. Затем:

```sh
git clone https://github.com/shoyo-22/learning-english.git
cd learning-english
```

Git скачивает только **опубликованные** коммиты. Если в скачанной версии нет команды `setup:demo` или каталога `docs`, используйте свежий учебный ZIP от автора: локальные изменения автора могут ещё не быть отправлены на GitHub. Для приватного репозитория доступ выдаёт его владелец; ZIP не требует GitHub-аккаунта.

## 4. Быстрый демо-запуск — рекомендуется начать здесь

В корне проекта:

```sh
npm ci
npm run setup:demo
npm run dev:local
```

1. `npm ci` устанавливает пакеты согласно lock-файлу. Дождитесь окончания без ошибки.
2. `setup:demo` создаёт готовый `.env.local` с локальными тестовыми настройками. Ничего вписывать вручную не нужно.
3. `dev:local` запускает сайт на вашем компьютере. Дождитесь сообщения **Ready**.

Откройте **http://localhost:3000**. Если терминал указал другой порт, используйте его. Оставьте терминал открытым на время работы. Для остановки нажмите **Ctrl+C** в этом терминале; на Windows подтвердите завершение, если будет запрос.

Проверьте: страница открывается, язык переключается между en/ru/kk, практика проверяет ответ, помощник возвращает подписанный демо-ответ. Сообщение о несохранённой практике и недоступные исследовательские тесты в этом режиме ожидаемы.

### Если в проекте уже есть `.env.local`

Скрипт **не заменяет вручную созданные или рабочие настройки**. Сообщение `Existing .env.local was preserved` означает, что файл сохранён, а не что установка сломана. Для обучения распакуйте отдельную чистую копию проекта в другую папку и повторите команды там. Так рабочая база и её настройки останутся в прежней копии.

Не копируйте `.env.local` автора в папку ученика. `.env.example` — шаблон, Next.js сам его не загружает. Все доступы локального режима описаны в [отдельном документе](TEST_CREDENTIALS.ru.md).

## 5. Полный локальный режим с сохранением

Используйте отдельную учебную копию на доверенном личном компьютере. Docker Desktop может публиковать порты тестовой базы в локальной сети; перед запуском прочитайте [пояснение о доступности портов](TEST_CREDENTIALS.ru.md#что-открыто-в-сети). Для школьной общей или публичной сети выбирайте демо либо готовый сайт учителя. Запустите Docker. Если сервер Next.js уже работает, остановите его через Ctrl+C. В корне проекта:

```sh
npm ci
npm run setup:local
npm run db:check
npm run dev:local
```

Если `npm ci` уже успешно выполняли и зависимости не менялись, повторять его не обязательно.

`setup:local` скачивает и запускает сервисы Supabase, применяет две миграции проекта и автоматически записывает URL и действующий серверный API-ключ локального экземпляра в `.env.local`. **Supabase-аккаунт, облачный проект, ручное выполнение SQL и ввод ключей не требуются.** Первый запуск заметно дольше последующих: дождитесь завершения загрузки образов и проверок здоровья.

`db:check` проверяет семь таблиц и функцию сводных результатов, не создавая участников. После успешной проверки откройте **http://localhost:3000/research**. Вместо сообщения о недоступной базе появятся реальные пустые результаты и возможность начать Before.

### Проверка учебного сценария на своей тестовой базе

1. В одном браузере выполните и сохраните входной тест **Before**.
2. Перейдите в «Практика», закончите хотя бы одно занятие и убедитесь, что результат **сохранён**.
3. Вернитесь в «Исследование», выполните и сохраните **After**.
4. Проверьте появление пары результатов в сводке.

Этот сценарий создаёт **тестовые записи в вашей локальной базе**. Не выполняйте его с вымышленными ответами на сайте реального исследования. Подготовленный чат не заменяет сохранённую практику и не открывает After.

Адрес для просмотра локальных таблиц — **http://127.0.0.1:54323** (Supabase Studio). В локальной Studio нет отдельного аккаунта учителя. Пароль PostgreSQL и сведения об API-ключах — в [тестовых доступах](TEST_CREDENTIALS.ru.md#3-полная-локальная-база).

### Повторный запуск на следующий день

Откройте Docker, затем терминал в той же папке:

```sh
npm run db:local:start
npm run db:check
npm run dev:local
```

`db:local:start` сохраняет существующий `.env.local` и данные, применяет только ещё не выполненные миграции. Если локальные API-ключи были обновлены или файл настроек потерян, используйте `npm run setup:local` и затем перезапустите Next.js.

### Как закончить работу

1. Остановите Next.js через Ctrl+C.
2. В той же папке выполните:

```sh
npm run db:local:stop
```

Остановка сохраняет данные в Docker volume. Закрытие вкладки браузера само по себе не выключает сервер. Не применяйте `supabase db reset`, `supabase stop --no-backup` или удаление Docker volumes как способ обычного выключения — это может удалить результаты.

### Переключение обратно на демо

Остановите Next.js, затем:

```sh
npm run setup:demo
npm run db:local:stop
npm run dev:local
```

База остаётся на диске, но приложение к ней не обращается. Для возврата выполните `setup:local` и перезапустите сайт. Скрипт сохраняет прежний `SESSION_SECRET`, чтобы не менять подпись анонимных cookies. Всё равно сохраняйте тот же браузер, профиль и адрес сайта.

## 6. Команды на каждый день

Все команды ниже запускаются из корня проекта.

| Команда                  | Когда использовать                                                               |
| ------------------------ | -------------------------------------------------------------------------------- |
| `npm ci`                 | Первый запуск или обновление lock-файла; устанавливает пакеты заново             |
| `npm run setup:demo`     | Создать / переключить управляемую локальную конфигурацию без базы                |
| `npm run setup:local`    | Запустить локальную базу и получить её настройки автоматически                   |
| `npm run db:local:start` | Запустить прежнюю локальную базу без изменения `.env.local`                      |
| `npm run db:local:stop`  | Остановить локальную базу с сохранением данных                                   |
| `npm run dev:local`      | Запустить сайт для обучения и редактирования на localhost                        |
| `npm run db:check`       | Проверить доступность схемы базы из `.env.local`                                 |
| `npm run typecheck`      | Проверить типы TypeScript                                                        |
| `npm run lint`           | Проверить код линтером                                                           |
| `npm test`               | Запустить автоматические тесты; стандартный запуск не обращается к облачной базе |
| `npm run build`          | Собрать production-версию                                                        |
| `npm run start:local`    | Запустить уже собранную production-версию на localhost                           |

Для репетиции запуска production-сборки остановите dev-сервер, затем:

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run start:local
```

После изменения исходников production-сборку нужно собрать заново. Во время обычной работы `dev:local` сам обновляет страницы. Не запускайте build и dev одновременно в одной папке: оба используют каталог `.next`.

## 7. Другой порт и сохранение результатов

Если порт 3000 занят:

```sh
npm run dev:local -- --port 3001
```

Откройте `http://localhost:3001`. Для собранной версии аналогично: `npm run start:local -- --port 3001`.

Локальные помощники оставляют `APP_URL` пустым, поэтому менять его из-за порта не нужно. Если вы настраивали `APP_URL` самостоятельно, значение должно точно совпадать с адресом сайта, включая протокол и порт.

Для исследования придерживайтесь одного адреса. `localhost` и `127.0.0.1` — разные имена сайта для браузера. Cookies также зависят от профиля; очистка данных, режим инкогнито или новый профиль разрывают связь Before / After. Удаление cookies не удаляет уже сохранённые записи в базе и не является процедурой удаления участника.

Локальные production-запуски в этой инструкции используют `localhost`: приложение выставляет защищённые cookies в production. Обычный HTTP по адресу компьютера в школьной сети не является проверенной заменой HTTPS для полного исследовательского сценария.

## 8. Как работать целым классом

Для демонстрации с проектора учителю достаточно своей локальной копии. Для самостоятельной практики без общей статистики ученики могут использовать свои демо-копии.

Для общего исследования технический ответственный готовит **один сервер с HTTPS и одной базой**. Ученикам передаётся только адрес сайта. На их компьютерах не нужны Node.js, Docker, пароли базы или серверные API-ключи.

`localhost` всегда означает текущий компьютер. Нельзя выдать классу ссылку `http://localhost:3000` и ожидать подключения к ноутбуку учителя. Локальные команды этой инструкции предназначены для одного компьютера и не публикуют школьный сайт. Настройка общего размещения описана технически в [README → Deploy to Vercel](../README.md#deploy-to-vercel); её выполняет ответственный за сервер.

В интерфейсе нет ролей student/teacher, закрытой учительской страницы и фильтра по классу. Методика занятия, отдельная база для реального исследования и порядок выгрузки данных описаны в [руководстве учителя](TEACHER_GUIDE.ru.md).

## 9. Необязательный вариант: своя облачная база Supabase

Этот раздел нужен администратору общего сайта или владельцу отдельного облачного проекта. **Для обычного демо и полного локального запуска он не требуется.**

1. Создайте собственный проект Supabase. Для реального сбора данных используйте отдельную базу, без тестовых участников.
2. В новой пустой базе выполните в SQL Editor содержимое файлов строго по порядку:
   - `supabase/migrations/202609050001_initial.sql`;
   - `supabase/migrations/202609050002_restore_schema_and_rpc.sql`.
3. Для существующей частично настроенной базы используйте инструкцию восстановления в [техническом README](../README.md#supabase-setup), не запускайте начальную миграцию поверх готовых таблиц.
4. Создайте `.env.local` в **отдельной серверной копии**. Не запускайте в ней `setup:demo` или `setup:local`.

```dotenv
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SECRET_KEY
SESSION_SECRET=YOUR_RANDOM_STRING_AT_LEAST_32_CHARACTERS
APP_URL=
```

Значения `YOUR_...` — места для **ваших собственных настроек**, а не готовые доступы. Получите URL и Secret key в панели конкретного проекта. Новый серверный ключ начинается с `sb_secret_`; также поддерживается старый `service_role`. Используйте тот тип, который выдаёт ваш проект.

Пример Supabase с `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` относится к клиентскому подключению. Здесь запросы к защищённым таблицам идут с сервера, поэтому нужен `SUPABASE_SERVICE_ROLE_KEY`, а публичный `sb_publishable_` его не заменяет. [Официальное описание ролей ключей](https://supabase.com/docs/guides/getting-started/api-keys).

Сгенерируйте `SESSION_SECRET`:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Запишите выданную строку в файл один раз и сохраняйте её между перезапусками. Не используйте публичную демо-строку для общего сайта. При размещении с постоянным адресом задайте `APP_URL` равным его HTTPS origin, без пути, например `https://classroom.example.org`.

Затем:

```sh
npm run db:check
npm run dev:local
```

Рабочие ключи хранятся только у владельца сервера. Учебный архив и документация содержат локальные тестовые доступы. Для Next.js серверные значения загружаются из `.env.local`; после их изменения перезапускайте процесс. [Документация Next.js о переменных окружения](https://nextjs.org/docs/app/guides/environment-variables).

## 10. Решение частых проблем

| Сообщение / симптом                           | Что делать                                                                                                                                                           |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node` или `npm` не найден                    | Установите Node 24 LTS, закройте и снова откройте терминал. Проверьте PATH / выбранную версию nvm.                                                                   |
| PowerShell запрещает `npm.ps1`                | Используйте `npm.cmd`, например `npm.cmd run dev:local`.                                                                                                             |
| `ENOENT ... package.json`                     | Вы открыли не ту папку. Найдите `package.json` и перейдите в неё через `cd`.                                                                                         |
| `Missing script: setup:demo`                  | Это старая опубликованная версия. Возьмите актуальный учебный ZIP.                                                                                                   |
| `npm ci` жалуется на несовпадение lock-файла  | Получите целую согласованную копию проекта. Не удаляйте lock-файл и не выполняйте массовое обновление пакетов накануне урока.                                        |
| npm сообщает сетевую ошибку                   | Проверьте интернет и школьный прокси, повторите `npm ci`. Не отключайте проверку TLS.                                                                                |
| `Existing .env.local was preserved`           | Настройки уже существуют. Используйте отдельную чистую копию; рабочий файл не затронут.                                                                              |
| Docker daemon недоступен                      | Откройте Docker Desktop, дождитесь готовности, выполните `docker info`; на Linux проверьте права учётной записи.                                                     |
| Supabase долго запускается впервые            | Docker скачивает большие образы. Дождитесь завершения. При явной ошибке проверьте сеть, свободное место и доступную Docker память, затем повторите команду.          |
| Порт 54321–54323 уже занят                    | Остановите предыдущий локальный Supabase из **его** папки. Не завершайте неизвестные процессы. В комплекте рассчитан один стек `english-lab-classroom` на компьютер. |
| Сайт не открывается                           | Проверьте Ready в терминале и точный адрес/порт. Терминал с сервером должен оставаться открытым.                                                                     |
| `next start` не находит production build      | Сначала выполните `npm run build`, потом `npm run start:local`.                                                                                                      |
| Практика проверяется, но не сохраняется       | Для демо это ожидаемо. Для полного режима проверьте Docker, `npm run db:check`, затем перезапустите Next.js.                                                         |
| Таблицы или RPC не найдены                    | В локальном режиме выполните `npm run db:local:start`. В облачном — примените миграцию восстановления по README.                                                     |
| After остаётся закрытым                       | Нужны сохранённый Before и завершённая **сохранённая практика после него** в том же браузере. Демо-чат этот этап не засчитывает.                                     |
| Ошибка origin / недопустимый источник запроса | Используйте постоянный адрес сайта. Если вручную задали `APP_URL`, исправьте его и перезапустите сервер. Не отключайте проверку origin.                              |
| Страница содержит старые изменения            | В dev обновите страницу; для production остановите процесс, повторите build и start. При обновлении будет потеряна незавершённая форма.                              |

Перед обращением за помощью запишите ОС, вывод `node --version`, какую команду выполняли и текст ошибки. Можно приложить снимок **сообщения об ошибке**. Не отправляйте содержимое `.env.local` или вывод команды с API-ключами в общий чат.

## 11. Обновление, резервные копии и передача проекта

Перед обновлением остановите сервер и локальную базу. Сохраните свою конфигурацию в закрытом месте. Для учебных результатов экспортируйте нужные таблицы из Studio в CSV; CSV — выгрузка для анализа, а не полная резервная копия базы. Полный backup/restore при реальном исследовании организует администратор. Не удаляйте Docker volumes, пока данные нужны.

Если получаете ZIP, распаковывайте новую версию в **новую папку**, сохранив старую до проверки. Старый и новый экземпляры с `project_id = english-lab-classroom` используют одну локальную базу на данном Docker-движке; новая папка сама по себе не создаёт чистую базу. Не запускайте эти копии одновременно. Изменение `project_id` и портов требует отдельной настройки, а стандартный помощник рассчитан на конфигурацию комплекта.

Если используете Git и локальных правок нет:

```sh
git status
git pull --ff-only
npm ci
```

При собственных изменениях сначала согласуйте их с преподавателем/разработчиком; не выполняйте `git reset --hard` ради обновления. После обновления полного режима выполните `db:local:start`, `db:check` и запустите сайт. Более новые миграции могут менять схему; откат исходников не откатывает базу автоматически.

Передавайте ученикам архив исходников с `package-lock.json`, каталогом `docs`, `scripts` и `supabase`. Не включайте `.env.local`, `.git`, `.next`, `node_modules`, выгрузки участников и локальное состояние Supabase. Каждый ученик устанавливает пакеты через `npm ci` и получает собственные локальные настройки через `setup:demo` или `setup:local`.
