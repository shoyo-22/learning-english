# Локальные тестовые доступы English Lab

[Все инструкции](README.ru.md) · [Установка](INSTALLATION.ru.md)

Это настройки **локальной учебной копии**. Они не дают доступ к облачному проекту автора. Для первого запуска не нужно просить у автора пароль или ключ.

## 1. Вход на сайт

| Параметр                             | Значение                                              |
| ------------------------------------ | ----------------------------------------------------- |
| Сайт на вашем компьютере             | `http://localhost:3000`                               |
| Логин ученика                        | Не используется                                       |
| Пароль ученика                       | Не используется                                       |
| Логин/пароль учителя в English Lab   | Не используются; отдельной панели учителя нет         |
| OpenAI API key                       | Не нужен; помощник отвечает подготовленными примерами |
| Аккаунт Supabase для локальной копии | Не нужен                                              |

## 2. Готовая конфигурация демо

Команда `npm run setup:demo` создаёт `.env.local` рядом с `package.json`. Набор значений ниже полностью пригоден для демонстрации без базы:

```dotenv
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
SESSION_SECRET=english-lab-local-demo-only-2026-not-for-deployment
APP_URL=
```

`SESSION_SECRET` в этом примере — **публичная тестовая строка**, а не ключ облачной базы. Применяйте её только в локальной учебной копии. В полном локальном режиме, запущенном сразу через `setup:local`, скрипт создаёт случайную строку. При переходе из демо строка сохраняется, чтобы не менять идентификаторы браузеров.

Предпочтительнее выполнить команду, чем создавать файл вручную: скрипт добавит служебную отметку, которая разрешает дальнейшее переключение локальных режимов. Файл, созданный вручную или уже содержащий рабочие настройки, скрипт не перезапишет.

В этом режиме доступна проверка ответов практики, но результат не сохраняется, а входной и итоговый исследовательские тесты отключены. Для их работы используйте следующий раздел.

## 3. Полная локальная база

После `npm ci` и запуска Docker выполните:

```sh
npm run setup:local
npm run db:check
```

Скрипт запускает Supabase, применяет миграции и записывает действительные ключи **вашего локального экземпляра** в `.env.local`. Значения не выводятся в обычный лог скрипта.

| Сервис / параметр                                        | Тестовое значение                                                                            |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Supabase API (`SUPABASE_URL`)                            | `http://127.0.0.1:54321`                                                                     |
| Supabase Studio — просмотр локальных таблиц и SQL Editor | `http://127.0.0.1:54323`                                                                     |
| Логин/пароль Studio                                      | В стандартной конфигурации CLI не требуются; доступность из сети зависит от Docker, см. ниже |
| PostgreSQL host                                          | `127.0.0.1`                                                                                  |
| PostgreSQL port                                          | `54322`                                                                                      |
| PostgreSQL database                                      | `postgres`                                                                                   |
| PostgreSQL user                                          | `postgres`                                                                                   |
| PostgreSQL password                                      | `postgres`                                                                                   |
| Строка прямого подключения для SQL-клиента               | `postgresql://postgres:postgres@127.0.0.1:54322/postgres`                                    |
| `SUPABASE_SERVICE_ROLE_KEY`                              | Автоматически берётся из `SECRET_KEY`, либо `SERVICE_ROLE_KEY` локального CLI                |
| `SESSION_SECRET`                                         | Создаётся при настройке и сохраняется между запусками                                        |
| `APP_URL`                                                | Пустая строка: приложение проверяет запросы относительно адреса входящего запроса            |

Параметры соответствуют включённому в проект `supabase/config.toml`. Стандартные локальные адреса и пароль PostgreSQL приведены также в [документации Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started).

### Посмотреть свои локальные API-ключи

Если нужно перенести настройки между **своими локальными тестовыми инструментами**, выполните:

```sh
npx supabase status -o json
```

Нужные поля:

```text
API_URL          → SUPABASE_URL
SECRET_KEY       → SUPABASE_SERVICE_ROLE_KEY
SERVICE_ROLE_KEY → запасной вариант, если SECRET_KEY отсутствует
```

`PUBLISHABLE_KEY` и `ANON_KEY` не подходят для защищённых серверных операций этого проекта. Имя переменной `SUPABASE_SERVICE_ROLE_KEY` сохранено для совместимости; в неё можно записывать новый ключ вида `sb_secret_...`. Это соответствует [ролям ключей Supabase](https://supabase.com/docs/guides/getting-started/api-keys).

Один заранее вставленный `sb_secret_...` не является универсальным ключом для всех компьютеров. Поэтому установка сама получает корректное значение для созданного экземпляра: в документации нет неработающего «общего ключа» или замаскированной строки, которую нужно угадывать.

### Что открыто в сети

Команды проекта создают Docker-сеть `english-lab-local` с предпочтительной привязкой к `127.0.0.1` и проверяют фактические привязки. **Docker Desktop может проигнорировать эту настройку и открыть порты 54321–54323 на сетевых интерфейсах.** Это воспроизведено при проверке на macOS; скрипт явно сообщает об этом. Сам адрес `127.0.0.1` в таблице не доказывает, что подключение с другого компьютера закрыто. Такое ограничение также описано в [обсуждении Supabase CLI](https://github.com/supabase/cli/issues/1397#issuecomment-4373096765).

Полный локальный стек предназначен для тестов на доверенном личном компьютере и в закрытой сети. В общей школьной или публичной сети используйте демо без Docker либо готовый HTTPS-сайт учителя; администратор может отдельно ограничить входящий доступ к портам базы средствами сети. В локальную тестовую базу не переносите реальные данные участников. После репетиции выполняйте `npm run db:local:stop`. Скрипт не изменяет глобальные настройки Docker и системный firewall.

Сам сайт при `dev:local` / `start:local` слушает только localhost. Публичный пароль `postgres` и локальные ключи не предназначены для публикации школьного сервера.

## 4. Облачная база для реального исследования

Для общей базы класса учитель или администратор создаёт отдельный Supabase-проект и хранит **его собственные** секреты на сервере. Такие значения не входят в этот документ или архив. Нужны:

- URL конкретного проекта;
- серверный Secret key (`sb_secret_...`) или legacy `service_role`;
- случайный `SESSION_SECRET` минимум из 32 символов;
- адрес опубликованного сайта, если задаётся `APP_URL`.

Новая случайная строка для серверной настройки генерируется без дополнительных программ:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Подробный порядок подключения — в [разделе об облачном Supabase](INSTALLATION.ru.md#cloud). Ученики открывают сайт и не получают серверный ключ. Для запуска без облачной базы используйте готовые локальные варианты выше.
