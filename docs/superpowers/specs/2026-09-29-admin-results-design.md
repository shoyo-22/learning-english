# Результаты тестов для админа: спецификация

Дата: 2026-09-29. Статус: дизайн согласован с заказчиком, план реализации ещё не написан.

## 1. Цель

Когда ученик проходит тест, результат сохраняется вместе с его именем или кодом, и администратор (учитель) видит этот результат в защищённой панели `/admin`. Панель также показывает результаты практики и позволяет скачать данные в CSV.

## 2. Что уже есть и чего не хватает

Уже работает:

- Результаты Before/After сохраняются в `assessments` через RPC `save_assessment`, практика сохраняется в `quiz_sessions` и `quiz_attempts` через `save_quiz`.
- Публичная страница `/research` показывает только агрегаты (`research_summary`).

Не хватает:

- Личности участника: каждая запись привязана лишь к анонимному идентификатору браузера (`anonymous_sessions.session_id`).
- Администратора: в приложении нет ни входа, ни панели учителя. Индивидуальные результаты видны только в панели Supabase.

## 3. Принятые решения

| Вопрос                    | Решение                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Как понять, чей результат | Одно поле «Имя или код». Ученик вводит настоящее имя или код, выданный учителем. Что вводить, решает учитель.       |
| Вход админа               | Один пароль `ADMIN_PASSWORD` из окружения, подписанная cookie. Supabase Auth и учётные записи учеников не вводятся. |
| Что видит админ           | Before/After по ученикам, результаты практики, экспорт в CSV. Ответы на отдельные вопросы теста не сохраняются.     |
| Где хранится имя          | В `anonymous_sessions.display_name`. Все результаты браузера получают имя через `session_id`, ничего не копируется. |
| Доступ к данным           | Только через SQL-функции для роли `service_role`, как у существующих RPC. Ключ `service_role` остаётся на сервере.  |

Не входит в работу: учётные записи учеников, роли, несколько админов, восстановление пароля, хранение ответов на вопросы, пагинация, редактирование и удаление результатов из панели.

## 4. База данных

Новая миграция `supabase/migrations/202609290001_participant_names_admin.sql`. Стиль и гарантии как у `202609050002_restore_schema_and_rpc.sql`: одна транзакция, `lock_timeout` и `statement_timeout`, безопасный повторный запуск, существующие строки не изменяются и не удаляются, в конце `notify pgrst, 'reload schema'`.

### 4.1. Колонка

`anonymous_sessions.display_name text`, допускает `null`. Ограничение `anonymous_sessions_display_name_len`: `display_name is null or char_length(display_name) between 2 and 40`. Ограничение добавляется только если его ещё нет.

### 4.2. `set_participant_name(p_session uuid, p_name text) returns text`

- Обрезает пробелы по краям и схлопывает подряд идущие пробелы в один.
- Вызывает исключение `invalid_name`, если после обработки длина не в диапазоне 2–40 символов или строка содержит управляющие символы (`[[:cntrl:]]`).
- Вызывает исключение `session_not_found`, если строки с таким `session_id` нет.
- Иначе обновляет `display_name` и `last_seen_at` и возвращает сохранённое имя.
- Имя можно менять; вступает в силу для всех прошлых и будущих результатов этого браузера.

### 4.3. `admin_results(p_version text, p_participant_limit integer default 500, p_practice_limit integer default 1000) returns jsonb`

Только чтение. Лимиты нужны, чтобы ответ оставался ограниченным: панель использует значения по умолчанию, экспорт CSV передаёт увеличенные (п. 8). Лимит должен быть от 1 до 50000, иначе исключение `invalid_limit`. Возвращает объект:

```json
{
  "summary": {
    "participants": 0,
    "named": 0,
    "pairs": 0,
    "before": null,
    "after": null,
    "difference": null,
    "practiceSessions": 0
  },
  "participants": [
    {
      "shortId": "a3f9c1",
      "name": "Айгерим",
      "before": {
        "total": 62.5,
        "vocabulary": 50,
        "grammar": 100,
        "speaking": 50,
        "writing": 50,
        "at": "2026-09-29T10:00:00Z"
      },
      "after": null,
      "difference": null,
      "lastActivityAt": "2026-09-29T10:00:00Z"
    }
  ],
  "practice": [
    {
      "shortId": "a3f9c1",
      "name": "Айгерим",
      "level": "A2",
      "category": "Grammar",
      "correct": 2,
      "total": 2,
      "percentage": 100,
      "completedAt": "2026-09-29T10:20:00Z"
    }
  ],
  "truncated": { "participants": false, "practice": false }
}
```

Правила:

- `participants` содержит по одной строке на браузер, у которого есть хотя бы один тест версии `p_version`. `before` или `after` равен `null`, если такого теста нет. Порядок: по времени последнего теста, новые сверху. Не более `p_participant_limit` строк.
- `practice` содержит завершённые практики всех браузеров, включая тех, кто не проходил тест. Порядок: новые сверху. Не более `p_practice_limit` строк.
- `truncated.participants` и `truncated.practice` равны `true`, если строк было больше лимита. Интерфейс обязан показать это пользователю, а экспорт обязан отказать (п. 8).
- `shortId` это первые 6 символов `session_id` в нижнем регистре. Полный `session_id` наружу не возвращается.
- `name` равен `null`, если имя не задано.
- `difference` равна `after.total - before.total`, округлена до одного знака, и задана только для завершённых пар. Пара завершена, если `after.at >= before.at` (то же правило, что в `research_summary`).
- `summary` считается по всем строкам без учёта лимитов: `participants` — число браузеров с тестом, `named` — из них с именем, `pairs` — завершённые пары, `before`, `after`, `difference` — средние по парам с одним знаком после запятой (`null`, если пар нет), `practiceSessions` — общее число практик.

### 4.4. Права

`revoke execute ... from public, anon, authenticated; grant execute ... to service_role;` для обеих новых функций. Права на таблицу `anonymous_sessions` не меняются: RLS остаётся включённым, доступа у `anon` и `authenticated` нет.

### 4.5. Сопутствующие файлы

- `scripts/check-supabase.mjs`: добавить `display_name` в список колонок `anonymous_sessions` и проверку `admin_results` (чтение; в форме результата проверяются `participants`, `practice`, `summary`). Мутирующую функцию `set_participant_name` не вызывать, в согласии с уже принятым правилом скрипта.
- `supabase/tests/smoke_rollback.sql`: добавить проверки прав и поведения новых функций внутри существующей откатываемой транзакции.

## 5. Имя ученика

### 5.1. API

- `POST /api/participant`, тело `{ "name": string }`. Проверяется схемой `participantSchema` (`z.string().trim().min(2).max(40)`, без управляющих символов, `strict`). Использует существующие `body()`, `session()`, `limit("participant:<id>", 20)`, `ensureSession()`, затем `set_participant_name`. Ответ `{ "name": string }`.
- Ошибки: `invalid_name` → 400 «Введите имя или код от 2 до 40 символов.»; отсутствие хранилища → 503 (уже покрыто `db()`); прочее → 503.
- `GET /api/session` дополняется полями `participantName: string | null` и `participantReady: boolean`. При недоступном хранилище `participantName` равен `null`, `participantReady` равен `false`. Поведение при отсутствующей колонке описано в п. 10.

### 5.2. Интерфейс

Общий клиентский компонент `ParticipantName` (`src/components/participant-name.tsx`): поле, кнопка «Сохранить», подпись «Введите имя или код, который дал учитель. Результат увидит учитель.» После сохранения показывает имя и кнопку «Изменить».

- На `/research`, блок теста: компонент стоит выше кнопок старта. Пока имя не сохранено, кнопки «Start Before Test» и «Start After Test» отключены и рядом стоит пояснение почему.
- На `/practice`: тот же компонент, необязательный. Практику можно проходить без имени; тогда админ видит «Без имени».
- Прошлые результаты: у кого Before сохранён без имени, блок покажет ту же просьбу. После сохранения имя относится ко всем прошлым результатам.

## 6. Вход админа

### 6.1. Настройка

Переменная `ADMIN_PASSWORD`, минимум 12 символов. Админ включён только если настроены и `dbConfigured()`, и `ADMIN_PASSWORD`. Пароля по умолчанию нет. Если админ не настроен, страница `/admin` показывает сообщение «Панель администратора не настроена», а маршруты возвращают 503.

- `.env.example`: добавить `ADMIN_PASSWORD=` с комментарием.
- `scripts/local-config.mjs`: в режиме `local` генерировать случайный `ADMIN_PASSWORD` (24 символа, hex или base64url) и сохранять между запусками так же, как `SESSION_SECRET`; в режиме `demo` оставлять пустым (админу нужна база). Существующее значение не перезаписывать.

### 6.2. Модуль `src/lib/admin-auth.ts`

Чистый модуль без `server-only` и без `next/headers`, чтобы его можно было тестировать `node:test`. Все секреты принимаются параметрами.

- `signAdminToken(secret, password, expiresAt)` → строка `"<expiresAtMs>.<hmacHex>"`. Ключ подписи выводится как HMAC-SHA256(`SESSION_SECRET`, `"admin:" + ADMIN_PASSWORD`), поэтому смена пароля отзывает все выданные cookie.
- `verifyAdminToken(token, secret, password, now)` → `boolean`. Проверяет формат, срок действия и подпись через `timingSafeEqual`. Любой некорректный ввод даёт `false`, а не исключение.
- `passwordMatches(input, expected)` → `boolean`. Сравнивает SHA-256 хэши через `timingSafeEqual`, чтобы длина пароля не влияла на время.

### 6.3. Серверная обвязка

`src/lib/server.ts` дополняется (или рядом создаётся `src/lib/admin.ts` с `import "server-only"`):

- `adminConfigured()`, `isAdmin()` (читает cookie `english_lab_admin` через `cookies()` и вызывает `verifyAdminToken`), выдача и очистка cookie.
- Параметры cookie: `httpOnly`, `sameSite: "strict"`, `secure` в production, `path: "/"`, `maxAge` 8 часов.
- Из `body()` выносится проверка origin в отдельную функцию `assertSameOrigin(request)`, которая используется и в `body()`, и в `DELETE` выхода. Поведение `body()` не меняется.

### 6.4. Маршруты

Каждый маршрут и страница сами вызывают `isAdmin()`; проверка не сводится к прокси. В приложении нет `proxy.ts` и вводить его не нужно.

| Маршрут                                            | Поведение                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/admin/session`                          | Тело `{ "password": string }` (`strict`, длина до 200). Два лимита `limit()`: 5 попыток в минуту на ключ клиента (`x-forwarded-for`, первый адрес, иначе `"unknown"`) и общий предел 20 попыток в минуту на весь сервер. Верно: cookie и `{ "ok": true }`. Неверно: 401 «Неверный пароль.». |
| `DELETE /api/admin/session`                        | `assertSameOrigin`, удаляет cookie, `{ "ok": true }`.                                                                                                                                                                                                                                       |
| `GET /api/admin/results`                           | Без админа 401. Иначе `admin_results(assessmentVersion)` и JSON в форме из п. 4.3.                                                                                                                                                                                                          |
| `GET /api/admin/export?kind=assessments\|practice` | Без админа 401; неизвестный `kind` 400. Иначе CSV (п. 8).                                                                                                                                                                                                                                   |

Все ответы с `Cache-Control: no-store`, ошибки через существующие `failure()` и `json()`.

Заголовок `x-forwarded-for` задаёт клиент, если перед приложением нет доверенного прокси, поэтому лимит по клиенту можно обойти подменой заголовка. Защиту от подбора обеспечивает общий предел вместе с длиной пароля от 12 символов. Цена такого решения: длительная атака может задерживать вход администратора, но не позволяет обойти пароль. Действующая сессия админа (8 часов) при этом не затрагивается.

## 7. Страница `/admin`

`src/app/admin/page.tsx`, серверный компонент. Метаданные: `robots: { index: false, follow: false }`, заголовок из переводов. В общее меню и футер ссылка не добавляется. В `Header` хлебная крошка берёт название раздела из списка ссылок и для `/admin` показала бы «Home», поэтому добавляется отдельная запись только для крошки.

- Админ не настроен → сообщение из п. 6.1.
- Нет валидной cookie → `AdminLogin` (клиентский компонент: поле пароля, кнопка «Войти», сообщение об ошибке).
- Есть валидная cookie → `AdminDashboard` (клиентский компонент).

### 7.1. `AdminDashboard`

- Загружает `/api/admin/results` при открытии и затем раз в 30 секунд; пауза, пока вкладка браузера скрыта. Кнопка «Обновить» запускает загрузку сразу. Показывает «Обновлено в ЧЧ:ММ:СС».
- 401 при загрузке возвращает форму входа. Кнопка «Выйти» вызывает `DELETE /api/admin/session`.
- Сводка: участников (из них с именем), завершённых пар, среднее Before, среднее After, разница (в процентных пунктах, как на `/research`), практик.
- Вкладки на компоненте `kit/tabs`:
  - **Before/After**: имя или код (или «Без имени»), `#shortId`, Before, After, разница, четыре навыка для Before и After, время последнего теста. Поиск по имени и `shortId`. Сортировка по имени, времени, Before, After, разнице.
  - **Практика**: имя или код, `#shortId`, уровень, категория, верно из N, процент, время. Поиск и сортировка по времени и проценту.
- Если `truncated.*` равно `true`, над таблицей показывается сообщение с числом показанных строк и пояснением, что остальные доступны в CSV или в панели Supabase.
- Пустые состояния: «Пока никто не проходил тест», «Пока нет результатов практики».
- Кнопки «Скачать CSV» на каждой вкладке ведут на `/api/admin/export`.
- Доступность: таблицы с `caption` и `th scope`, кнопки с текстом, фокус после входа и выхода, как в остальных формах проекта.
- Все новые строки интерфейса проходят через `tr()` и имеют переводы en/ru/kk в `src/lib/i18n/messages.json`.

## 8. CSV

Чистый модуль `src/lib/csv.ts` без зависимостей от Next.

- Разделитель запятая, перевод строки `\r\n`, значения с запятой, кавычкой или переводом строки берутся в кавычки, кавычки удваиваются.
- Файл начинается с BOM `﻿`, чтобы Excel правильно читал кириллицу.
- Ячейка, начинающаяся с `=`, `+`, `-`, `@`, табуляции или возврата каретки, получает в начале апостроф `'`, чтобы имя вида `=HYPERLINK(...)` не стало формулой. Числа выводятся числами без такой защиты.
- Даты в ISO 8601 UTC.
- Колонки `assessments`: `name, short_id, before_total, before_vocabulary, before_grammar, before_speaking, before_writing, before_at, after_total, after_vocabulary, after_grammar, after_speaking, after_writing, after_at, difference`.
- Колонки `practice`: `name, short_id, level, category, correct, total, percentage, completed_at`.
- Заголовок ответа: `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="english-lab-<kind>-<YYYY-MM-DD>.csv"`.
- Экспорт вызывает `admin_results` с увеличенными лимитами: 5000 участников и 20000 практик. Если и этого не хватило (`truncated` равно `true` для запрошенной выборки), экспорт отвечает 413 с сообщением «Слишком много записей для экспорта. Выгрузите таблицу из панели Supabase.» и не отдаёт неполный файл. Неполный CSV, выглядящий полным, хуже отказа.

## 9. Приватность и безопасность

- Публичные `/api/research` и `/research` остаются анонимными; имена в них не попадают.
- Имя выводится только React-экранированным текстом и в CSV с защитой от формул. HTML из имени не интерпретируется нигде.
- Полный `session_id` не отправляется в браузер админа и не попадает в CSV.
- Тексты, обещающие анонимность, обновляются: `About`, `docs/TEACHER_GUIDE.ru.md` (раздел про данные и утверждение об отсутствии панели учителя), `docs/STUDENT_GUIDE.ru.md`, `docs/TEST_CREDENTIALS.ru.md` (строка «логин/пароль учителя»), `docs/INSTALLATION.ru.md`, `README.md`, подписи в `research-dashboard.tsx`. Рядом с полем имени сказано, что результат увидит учитель.
- Ограничение, которое остаётся: без учётных записей два ученика могут ввести одно имя, а один ученик на другом устройстве получит другой идентификатор. Рядом с именем всегда виден `#shortId`. Это записывается в руководство учителя.
- Пароль админа и подписанная cookie не логируются. Значение `ADMIN_PASSWORD` не выводится скриптами настройки.

## 10. Ошибки и совместимость

- Миграция не применена: `/api/admin/results` и `/api/participant` возвращают 503 с понятным текстом «Обновите схему базы данных: примените последнюю миграцию.»; админ-панель показывает его вместо таблицы.
- `GET /api/session` читает `display_name` отдельным запросом, ошибка которого не ломает весь ответ. Иначе отсутствие колонки сломало бы историю практики и статус теста у всех учеников. При ошибке возвращается `participantName: null` и `participantReady: false`.
- При `participantReady: false` компонент `ParticipantName` показывает то же сообщение об обновлении схемы. Практика продолжает работать. Кнопки Before и After остаются отключёнными, потому что имя обязательно, а сохранить его нельзя. Это сознательный выбор: тест без имени не решает задачу заказчика и создал бы записи «Без имени». Поэтому миграцию нужно применить до того, как ученики начнут проходить тест с новым кодом.
- Ошибки сети и таймауты в панели показываются сообщением с кнопкой «Обновить», а не пустой таблицей.
- Существующие данные без имени показываются как «Без имени» и остаются в общих агрегатах.

## 11. Облачная база

`.env.local` проекта указывает на облачный Supabase. Реализация подготавливает миграцию и проверки, но не применяет миграцию к облачной базе. Заказчик выполняет файл миграции целиком в SQL Editor, затем `npm run db:check`. Миграцию нужно применить до того, как ученики начнут проходить тест с новым кодом (п. 10). Для локальной базы миграция применяется штатным `npm run setup:local` / `db:local:start`. До применения миграции сквозная проверка на облаке невозможна; она выполняется на pglite-тестах и, если доступен Docker, на локальной базе Supabase. Для ручной проверки используется одноразовый пароль, переданный через окружение процесса, а не записанный в файлы.
